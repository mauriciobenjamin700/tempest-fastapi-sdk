    tempest_fastapi_sdk.eventsourcing¶

    Event sourcing: o protocolo de event store com backends SQL e KurrentDB.

    « Tempo real e mensageria

    eventsourcing ¶

    Event sourcing — an event store protocol with SQL and KurrentDB backends.

    • :class:EventStore — the protocol: append with optimistic concurrency, read a stream forwards or backwards, read and subscribe to the store-wide log ($all) by position, snapshots.
    • :class:SqlEventStore — on the PostgreSQL / SQLite the service already has, over the abstract tables in :mod:~tempest_fastapi_sdk.eventsourcing.models; can write every event to the transactional outbox in the same transaction.
    • :class:KurrentDBEventStore — on KurrentDB, through the official client (kurrentdb extra, imported only when used).
    • :class:DomainEvent + :class:EventRegistry — typed Pydantic payloads, stored by type name.
    • :class:Aggregate + :class:AggregateRepository — load by replay (after a snapshot), save by one append.
    • :class:ProjectionRunner — feed a read model from $all and a checkpoint.

    Both stores raise :class:~tempest_fastapi_sdk.WrongExpectedVersionException (409) when an append's expected_version does not match the stream.

    DomainEvent ¶

    Bases: BaseModel

    Base class for the typed payload of an event.

    Subclass it once per event and register the subclass in an :class:EventRegistry. The stored type name is the class attribute event_type when the subclass declares one, otherwise the class name — declare it explicitly once events are stored, so renaming the class does not orphan the rows already written under the old name.

    Instances are frozen: an event is a fact that already happened. Unknown fields are ignored on decode, so removing a field from the class keeps old events readable; adding a field needs a default for the same reason.

    This is a plain Pydantic model on purpose, not :class:~tempest_fastapi_sdk.BaseSchema: that base strips whitespace from every string, which would store a different payload from the one the caller built.

    Example

    class OrderPlaced(DomainEvent): ... event_type: ClassVar[str] = "order.placed" ... order_id: str ... total_cents: int

    StreamStateEnum ¶

    Bases: StrEnum

    Expected stream states that are not an exact version number.

    • ANY — append whatever the stream holds (no concurrency check).
    • NO_STREAM — the stream must not exist yet (creating an aggregate).
    • EXISTS — the stream must exist, at any version.

    EventStore ¶

    WrongExpectedVersionException ¶

    WrongExpectedVersionException(
    stream_id: str, *, expected_version: int | str, actual_version: int | None
)

    Bases: ConflictException

    Raised when an append's expected_version does not match the stream.

    This is the optimistic-concurrency failure of an event store: someone else appended to the stream between the read that produced expected_version and this append. Both backends raise it — the SQL store from its conditional UPDATE of the stream row, the KurrentDB store by translating the client's WrongCurrentVersionError — so a service handles one exception whatever the backend.

    The usual reaction is to reload the aggregate and decide again; retrying the same append blindly would discard the other writer's decision.

    stream_id str

    expected_version int | str

    actual_version int | None

    The stream's last version when the append was refused, or None when the stream does not exist.
