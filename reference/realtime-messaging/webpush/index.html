    WebPushDispatcher ¶

    WebPushDispatcher(
    vapid_private_key: str,
    *,
    vapid_subject: str,
    ttl_seconds: int = 60,
    extra_vapid_claims: dict[str, str] | None = None,
    timeout: float = DEFAULT_WEBPUSH_TIMEOUT,
    allow_private_networks: bool = False,
    resolver: Resolver | None = None,
    prune_after_dns_refusals: int | None = DEFAULT_PRUNE_AFTER_DNS_REFUSALS,
    dns_refusal_window_seconds: float = DEFAULT_DNS_REFUSAL_WINDOW_SECONDS,
    clock: Callable[[], float] = monotonic,
)

    Send VAPID-signed Web Push notifications to browser subscribers.

    Wraps the synchronous pywebpush library in :func:asyncio.to_thread so dispatch fits the SDK's async-first convention. Subscriptions that respond with 404/410 raise :class:WebPushGoneError so the caller can prune their store; every other failure raises :class:WebPushError.

    Attributes:

    Name Type Description
    vapid_private_key str

    VAPID private key (PEM or base64url encoded). MUST match the public key advertised to clients.
    vapid_claims dict[str, str]

    Mandatory JWT claims attached to every push. sub is required (typically mailto:ops@example.com).
    ttl_seconds int

    Default time-to-live applied to each push (the push service buffers the payload for at most this long when the device is offline).
    timeout float

    Seconds each dispatch waits to connect and for each read before it fails with :class:WebPushError.
    allow_private_networks bool

    Whether endpoints resolving to loopback, private, link-local or otherwise non-public addresses are dispatched to.

    Initialize the dispatcher.

    Parameters:

    Name Type Description Default
    vapid_private_key str

    VAPID private key.

    		 required
    vapid_subject str

    The sub JWT claim. Browsers expect either a mailto: or https: URI.

    		 required
    ttl_seconds int

    Default TTL for delivered messages.

    		 60
    extra_vapid_claims dict[str, str] | None

    Additional claims merged into the JWT.

    		 None
    timeout float

    Connect and read timeout, in seconds, of every dispatch.

    		 DEFAULT_WEBPUSH_TIMEOUT
    allow_private_networks bool

    Skip the public-address check, for a self-hosted push service on the internal network. Redirects stay disabled and the timeout still applies. Only turn this on when subscribers are trusted.

    		 False
    resolver Resolver | None

    Async hostname → addresses lookup used by the public-address check; the first address it returns is the one the dispatch connects to. None uses the event loop's getaddrinfo.

    		 None
    prune_after_dns_refusals int | None

    How many consecutive :meth:send_many refusals decided by a DNS answer turn an endpoint into one :meth:prune removes. One such refusal is kept, because the answer can change; an endpoint whose host keeps resolving to a non-public address (a rebinding subscription) is otherwise never removed and costs a lookup and a log line on every fan-out. The refusals must also span dns_refusal_window_seconds, so three fan-outs in a row during a passing resolver problem prune nothing. A delivery that goes through resets the count; any other failure (a timeout, a lookup error) neither counts nor resets. An endpoint listed twice in one call counts once. A host of a browser push service (:data:KNOWN_PUSH_SERVICE_HOSTS) is never pruned this way, since its refusal means the deployment's resolver is wrong; a self-hosted push service on the internal network is not in that list, so serve it with allow_private_networks=True (nothing is refused then) or pass None here. The counts live in this instance, bounded to :data:MAX_TRACKED_DNS_REFUSALS endpoints. None disables pruning on DNS refusals.

    		 DEFAULT_PRUNE_AFTER_DNS_REFUSALS
    dns_refusal_window_seconds float

    Least time, in seconds, between the first counted refusal and the one that prunes.

    		 DEFAULT_DNS_REFUSAL_WINDOW_SECONDS
    clock Callable[[], float]

    Monotonic time source for the window (tests).

    		 monotonic

    Raises:

    Type Description
    ValueError

    When prune_after_dns_refusals is below 1, dns_refusal_window_seconds is negative, or the sub claim (vapid_subject, or a "sub" in extra_vapid_claims) is not mailto:<email> nor https://<host> — the format py_vapid signs with, so the fault surfaces here instead of on the first push (#791).

    send_many async ¶

    send_many(
    subscriptions: list[WebPushSubscriptionSchema],
    payload: WebPushPayloadSchema | dict[str, Any] | str | bytes,
    *,
    ttl_seconds: int | None = None,
    headers: dict[str, str] | None = None,
    max_concurrency: int | None = None,
) -> list[str]

    Fan out a single payload to many subscriptions.

    Dispatches run concurrently via :func:asyncio.gather. Only subscriptions that can never be delivered are returned — the ones the push service reports as dead, and the ones the egress check refuses permanently (see :attr:WebPushEndpointRefusedError.permanent: not https, or an IP-literal host that is not public). The list is what :meth:prune consumes, so an endpoint that failed for a transient reason must not be in it: a refusal decided by a DNS answer is logged and kept, because the answer can change -- until it repeats prune_after_dns_refusals times in a row across calls, when the endpoint is returned too.

    Parameters:

    Name Type Description Default
    subscriptions list[WebPushSubscriptionSchema]

    Recipients.

    		 required
    payload WebPushPayloadSchema | dict[str, Any] | str | bytes

    The notification body (same shapes as :meth:send).

    		 required
    ttl_seconds int | None

    Override TTL.

    		 None
    headers dict[str, str] | None

    Extra HTTP headers.

    		 None
    max_concurrency int | None

A global fan-out should pass a bound — every dispatch is a TLS request to a push service, and thousands at once earn a rate limit rather than a faster send. Values below 1 are treated as unbounded.

    WebPushConfigurationError ¶

    WebPushConfigurationError(
    message: str, *, status_code: int | None = None, endpoint: str | None = None
)

    Bases: WebPushError

    Raised when the dispatcher's own VAPID configuration cannot sign.

    A configuration fault, not a delivery one: it fails the same way for every subscription, so :meth:WebPushDispatcher.send_many raises it rather than logging it per subscriber. The dispatcher checks the sub claim on construction; this covers what that check cannot see, a claim changed afterwards, by turning py_vapid's VapidException into a typed error. A malformed private key is not covered: pywebpush raises binascii.Error (a ValueError) for it, before py_vapid signs anything.

    subscribe async ¶

    subscribe(
    user_id: UUID,
    subscription: WebPushSubscriptionSchema,
    *,
    user_agent: str | None = None,
    transfer_ownership: bool = False,
) -> SubscriptionModelT

    Persist a subscription, idempotently keyed by endpoint.

    The unique endpoint is the device identity. The same owner re-subscribing updates the keys, expiration_time and user_agent of the existing row instead of creating a duplicate.

    The endpoint is checked first with :meth:WebPushDispatcher.check_endpoint on :attr:dispatcher: one that dispatcher would refuse to deliver to (not https, or naming or resolving to a loopback, private, link-local or otherwise non-public address) raises :class:PushEndpointNotPublicException and is not stored, so allow_private_networks and resolver on the dispatcher govern registration and delivery alike. A host that does not resolve at that moment is accepted; every send re-checks.

    An endpoint already registered to another account is left untouched (#632): knowing an endpoint and supplying keys must not be enough to take a device from its owner, who would stop receiving their own notifications while they are encrypted for the caller. The row comes back unchanged and the routers answer exactly as for a new subscription, so the call cannot tell whether the endpoint belongs to someone else — the same rule :meth:unsubscribe follows. Two accounts on one browser share one PushSubscription: the client unsubscribes on sign-out, before the next account subscribes.

    unsubscribe async ¶

    unsubscribe(endpoint: str, *, user_id: UUID | None = None) -> bool

    Remove the subscription with endpoint, if present.

    Idempotent: removing an endpoint that is not stored is a no-op.

    With user_id the delete is scoped to that owner: a row holding endpoint that belongs to someone else is left untouched and the call answers False, exactly as for an unknown endpoint, so the caller cannot learn whether the endpoint is registered to another account. Every request-driven path must pass it. None keeps the unscoped delete for internal maintenance, such as pruning an endpoint the push service answered 404/410 for.

    notify_all async ¶

    notify_all(
    payload: WebPushPayloadSchema | dict[str, Any] | str | bytes,
    *,
    ttl_seconds: int | None = None,
    exclude_endpoints: list[str] | None = None,
    page_size: int = _DEFAULT_BROADCAST_PAGE_SIZE,
    max_concurrency: int | None = _DEFAULT_BROADCAST_CONCURRENCY,
) -> int

    Send payload to every stored device, pruning the dead ones.

    The global counterpart of :meth:notify_user: same delivery, same automatic pruning, no user_id filter. Use it for the announcement that is not about one account — maintenance window, release notice, campaign.

    Two things differ from :meth:notify_user, and both are about size. The table is walked in batches of page_size rather than loaded whole, so memory does not scale with the subscriber base. And the dispatch fan-out is bounded by max_concurrency, because every dispatch is a request to a push service and thousands at once earn a rate limit.

    The walk is cursor-based, not offset-based, precisely because this method deletes as it goes: an offset would skip a row for every row pruned on an earlier page. Rows created while the broadcast runs are not visited — the cursor moves from newest to oldest, and a new subscription is newer than the page already passed. That is what makes the walk terminate.

    WebPushPayloadSchema ¶

    Bases: BaseSchema

    JSON payload delivered with each push, in the shape the service worker reads.

    Mirrors tempest-react-sdk's PushPayload (v0.86.0), pinned by tests/webpush/test_payload_contract.py: the field names on the wire are the ones installPushHandler reads, so :meth:to_json serializes by alias (requireInteraction) and drops None fields, leaving the browser defaults in place.

    The click destination is the top-level url. The React push handler writes data.url from it after spreading data, so a free-form data bag cannot redirect the click, and a url placed only inside data is ignored: every click opens /. Earlier releases of this schema documented data={"url": ...}, so construction and assignment lift a string data["url"] into url when url is absent or None. An empty string counts as a value and is not replaced. When both are given and differ, the top-level url wins and a warning is logged.

    The React click handler's default resolver opens only pages of the worker's own origin over http(s): a url on another origin, or with another scheme, opens / unless the app installs its own resolveUrl.
