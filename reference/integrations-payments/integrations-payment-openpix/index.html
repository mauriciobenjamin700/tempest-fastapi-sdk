    Two behaviours are deliberate. An unrecognized event name does not fail the request: OpenPix adds events, and a service that 500s on one it has never seen turns a provider's release into its own outage — the name is kept as event_name with event left None. A body that is not JSON is also not an error here; it verified, so it came from OpenPix, and rejecting it would discard a delivery the provider considers sent. payload stays empty and body carries the bytes.
