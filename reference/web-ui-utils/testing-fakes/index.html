    FakePixProvider ¶

    FakePixProvider(*, provider_name: str = 'fake')

    Bases: _Steerable

    A PixRefundProvider that keeps charges and refunds in dicts.

    Refunds follow the contract the real adapters keep: idempotent on refund_reference per charge, partial refunds summed, a refund above what is left refused with :class:~tempest_fastapi_sdk.exceptions.PixRefundExceedsBalanceException. Only a PAID charge (or a REFUNDED one, for the replay and the balance error) can be refunded; anything else raises ValueError. :meth:fail_after_next_refund reproduces the case idempotency exists for: the refund lands and the answer is lost.

    Example:

    >>> provider = FakePixProvider()
>>> charge = await provider.create_pix_charge(
...     PixChargeRequest(amount_cents=1990, reference="order-1"),
... )
>>> event = provider.advance(charge.provider_charge_id, PaymentStatusEnum.PAID)
>>> event.type is PixEventTypeEnum.CHARGE_PAID
True

    FakeCardProvider ¶

    FakeCardProvider(*, provider_name: str = 'fake')

    Bases: _Steerable

    A CardProvider that keeps charges in a dict.

    A charge is approved unless :meth:decline_next queued a decline, which comes back as a :attr:PaymentStatusEnum.FAILED charge — returned, not raised, as the real adapter returns the provider's HTTP 402. A capture=False request comes back :attr:PaymentStatusEnum.AUTHORIZED.

    The fake refuses the transitions a real provider refuses, with ValueError: capturing or cancelling anything but an authorization, refunding anything but a paid charge, refunding more than is left. The real adapter raises httpx.HTTPStatusError there instead; what this fake guarantees is that the branch is reachable, not the exception type.

    Example:

    >>> provider = FakeCardProvider()
>>> charge = await provider.create_card_charge(
...     CardChargeRequest(
...         amount_cents=10000,
...         reference="order-1",
...         card_token="tok",
...         payment_method_id="visa",
...     ),
... )
>>> refunded = await provider.refund_card_charge(
...     charge.provider_charge_id, amount_cents=3000
... )
>>> (refunded.status, refunded.refunded_cents)
(<PaymentStatusEnum.PAID: 'paid'>, 3000)

    make_fake_orders_app ¶

    make_fake_orders_app(api: FakeMercadoPagoOrdersAPI) -> FastAPI

    Serve a simulator over HTTP, for a service running on its own.

    tempest mercado-pago fake-api runs it under uvicorn. Every /v1/orders route answers as the in-process handler does, and :data:FAKE_CONTROL_PREFIX adds:

    • GET /_fake/orders — every order id.
    • GET /_fake/orders/{reference} — one order, by id or by external_reference (:meth:FakeMercadoPagoOrdersAPI.find_order_id); 404 when none matches.
    • POST /_fake/orders/{reference}/{transition} — resolve the order the same way, apply :meth:FakeMercadoPagoOrdersAPI.apply (?amount_cents= for a partial refund) and answer {"order": <order>, "action": <action>}. The delivery itself is not sent: the server does not know the service's secret, so tempest mercado-pago simulate-webhook (or the simulation routes of make_mercado_pago_router(simulation_url=...)) signs and sends it.
