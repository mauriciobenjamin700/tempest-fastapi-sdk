    tempest_fastapi_sdk.privacy¶

    Exportação e apagamento de dados do titular (LGPD art. 18, GDPR art. 15/17).

    « Documentos e arquivos

    privacy ¶

    Data-subject export and erasure (LGPD art. 18, GDPR art. 15/17).

    Two halves, one per place personal data lives:

    • :class:SubjectGraph derives, from SQLAlchemy MetaData, the tables a delete of the subject's root row cascades to, exports one subject's rows without secret columns, and lists the foreign keys that would break erasure (:func:~tempest_fastapi_sdk.testing.assert_subject_graph_valid turns that into a CI guard);
    • :class:SubjectObjectStorage keeps every object of a subject under one prefix of an :class:~tempest_fastapi_sdk.storage.AsyncMinIOClient and erases the prefix in S3 batch deletes.

    SubjectGraph needs only SQLAlchemy (base install). SubjectObjectStorage needs a client, which needs the [minio] extra; importing this package does not.

    DEFAULT_SECRET_MARKERS module-attribute ¶

    DEFAULT_SECRET_MARKERS: tuple[str, ...] = ('hash', 'secret', 'password')

    Substrings that mark a column as secret by name (case-insensitive).

    A column whose name contains any of them (password_hash, totp_secret, api_key_hash) is left out of :meth:SubjectGraph.export. Mark a column explicitly with mapped_column(..., info={"secret": True}) or list it in secret_columns when the name says nothing.

    SECRET_INFO_KEY module-attribute ¶

    SECRET_INFO_KEY: str = 'secret'

    Key of Column.info that marks a column as secret when truthy.

    SubjectGraph ¶

    SubjectGraph(
    metadata: MetaData,
    *,
    root: str | Table,
    retained: Mapping[str, str] | None = None,
    secret_columns: Mapping[str, Collection[str]] | None = None,
    secret_markers: Collection[str] = DEFAULT_SECRET_MARKERS,
    exclude_binary: bool = True,
    value_matches: Mapping[str, str] | None = None,
)

    Cascade closure of a data subject, read from SQLAlchemy metadata.

    Example:

    >>> graph = SubjectGraph(Base.metadata, root="users")
>>> graph.tables()
['users', 'addresses', 'orders', 'order_items']
>>> graph.violations()
[]
>>> payload = await graph.export(session, user_id)
>>> payload["orders"][0]["total"]
'19.90'

    secret_columns dict[str, frozenset[str]]

    Extra columns per table left out of the export.
    secret_markers tuple[str, ...]

    Parameters:

    Name Type Description Default
    metadata MetaData

    Metadata holding every table of the service (Base.metadata).

    		 required
    root str | Table

    The subject's root table, by name or object. Its single-column primary key is the subject id.

    		 required
    retained Mapping[str, str] | None

    Foreign keys that may point into the closure with ON DELETE SET NULL because the row is kept after erasure (an invoice the tax law requires, a message in a shared thread). Keys are "table.column" ("table.col_a,col_b" for a composite key), values are the reason.     		 None
    secret_columns Mapping[str, Collection[str]] | None

    		 None
    secret_markers Collection[str]

    Case-insensitive substrings of a column name that mark it as secret. Defaults to :data:DEFAULT_SECRET_MARKERS.

    		 DEFAULT_SECRET_MARKERS
    exclude_binary bool

    Leave LargeBinary columns (and its subclasses) out of the export. A queue payload or a model blob is not data the subject can read, and in base64 it is only volume. False keeps them, base64-encoded.

    		 True
    value_matches Mapping[str, str] | None

    Columns that identify the subject by value rather than by foreign key — an invite sent to the subject keeps their e-mail in invites.to_email while its key points at the sender. Keys are "table.column" of a closure table, values are the key of the values mapping that :meth:condition, :meth:export, :meth:count and :meth:erase receive ({"invites.to_email": "email"} with values={"email": "ana@example.com"}). An entry outside the closure or naming a missing column is reported by :meth:violations.

    		 None

    Raises:

    Type Description
    KeyError

    When root names a table missing from metadata.
    ValueError

    When the root table does not have exactly one primary-key column.

    violations ¶

    violations() -> list[str]

    List every foreign key that would break erasure of a subject.

    A foreign key whose target table is in the closure must cascade, or be a nullable SET NULL key listed in retained. Anything else (NO ACTION, RESTRICT, an unlisted SET NULL) makes the root delete fail or leaves the subject's id behind. Stale retained entries are reported too, so the allowlist cannot rot.

    Returns:

    Type Description
    list[str]

    list[str]: One human-readable line per problem, sorted. Empty
    list[str]

    list when the schema supports erasure.

    condition ¶

    condition(
    table: str | Table, subject_id: object, *, values: Mapping[str, Any] | None = None
) -> ColumnElement[bool]

    Build the WHERE clause selecting one subject's rows of a table.

    The root matches on its primary key. Any other table matches when one of its cascading foreign keys points at a row of a closure table that itself belongs to the subject, as a nested IN (SELECT ...). A row reachable only through a cycle back to its own table (a reply to a reply, by another subject) is not considered the subject's. A table listed in value_matches also matches when its column equals the given value, and so do the rows that cascade from it.

    erase async ¶

    erase(
    session: AsyncSession,
    subject_id: object,
    *,
    values: Mapping[str, Any] | None = None,
) -> dict[str, int]

    Delete one subject's rows and return the proof.

    Deletes the rows each value_matches entry selects (the database cascades from them), then the root row (the database cascades the rest of the closure), flushes, and returns :meth:count — which should be 0 everywhere. It does not commit: the caller decides, and can roll back when the proof is not clean.

    Name Type Description Default
    session AsyncSession

    An open async session. The ON DELETE rules must be enforced by the connection (on SQLite, with foreign keys on, which the SDK's engines turn on).

    		 required
    subject_id object

    The value of the root's primary key.

    		 required
    values Mapping[str, Any] | None

    The subject's identifying values, for the tables in value_matches.

    		 None

    Returns:

    Type Description
    dict[str, int]

    dict[str, int]: :meth:count after the deletes.

    SubjectObjectStorage ¶

    SubjectObjectStorage(
    client: SubjectStorageClient, *, prefix: str = "subjects", bucket: str | None = None
)

    Store objects under a per-subject prefix and erase them in batch.

    Example:

    >>> storage = SubjectObjectStorage(client, prefix="users")
>>> await storage.put(user_id, "avatar.png", data, content_type="image/png")
'users/42/avatar.png'
>>> await storage.presign(user_id, "avatar.png")
'https://...'
>>> await storage.presign_put(user_id, "upload.jpg")
'https://...'
>>> await storage.read(user_id, "upload.jpg", max_bytes=1_048_577)
b'...'
>>> await storage.delete_all(user_id)
1

    presign_put async ¶

    presign_put(
    subject_id: object, name: str, *, expires: timedelta = timedelta(minutes=15)
) -> str

    Generate a temporary upload URL for one subject's object.

    The client PUTs the bytes straight to the store, so they never cross the API process. The URL only reaches key(subject_id, name): the subject prefix is fixed by the server when it signs, never by the uploader. Nothing about the payload is signed — size and content type are whatever the client sends — so verify the object with :meth:stat and :meth:read before trusting it, or issue :meth:presign_post, whose size and type the store enforces.

    read async ¶

    read(subject_id: object, name: str, *, max_bytes: int | None = None) -> bytes

    Read one subject's object into memory, optionally capped.

    With max_bytes, only the first max_bytes bytes are requested from the store (a Range read through :meth:~tempest_fastapi_sdk.storage.AsyncMinIOClient.stream_object), and reading stops there even if the store answers with more. An object that was swapped for a larger one after a :meth:stat never enters memory whole.

    To detect "too large", pass limit + 1 and compare the length: len(data) > limit means the object exceeds limit, without reading the rest of it.
