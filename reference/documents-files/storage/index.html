    AsyncMinIOClient ¶

    AsyncMinIOClient(
    endpoint: str,
    access_key: str,
    secret_key: str,
    *,
    default_bucket: str = "uploads",
    secure: bool = False,
    region: str = "us-east-1",
    session_token: str | None = None,
    public_endpoint: str | None = None,
    public_secure: bool | None = None,
    accel_redirect: bool = False,
    accel_prefix: str = "/_bucket/",
    enabled: bool = True,
)

    Async-friendly facade over minio.Minio.

    Use as an async context manager when you want explicit cleanup, or hold a long-lived instance on the FastAPI app — the underlying Minio client is thread-safe and reuses its connection pool.

    Example:

    >>> from tempest_fastapi_sdk import AsyncMinIOClient
>>> storage = AsyncMinIOClient(
...     endpoint="localhost:9000",
...     access_key="minioadmin",
...     secret_key="minioadmin",
...     default_bucket="uploads",
... )
>>> await storage.ensure_bucket()
>>> await storage.put_object("hello.txt", b"world")
>>> body = await storage.get_object_bytes("hello.txt")
>>> assert body == b"world"

    host[:port] without scheme. Used for every server-side operation.

    		 required
    access_key str

    S3 access key.

    		 required
    secret_key str

    S3 secret key.

    		 required
    default_bucket str

    Bucket used by object operations when no explicit bucket keyword is passed. Created by :meth:ensure_bucket.

    		 'uploads'
    secure bool

    Use HTTPS when True.

    		 False
    region str

    S3 region. Match the bucket region for AWS S3; any value works for MinIO.

    		 'us-east-1'

    Optional STS session token for temporary credentials.

    		 None
    public_endpoint str | None

    Split-endpoint mode. When set, presigned URLs (:meth:presigned_get_url / :meth:presigned_put_url) are signed against this host instead of endpoint — for deployments where the backend reaches MinIO over a private network but the browser must hit a public, TLS-terminated host. A scheme:// prefix and any trailing path are stripped, and https:// implies public_secure=True. None signs presigned URLs with endpoint (unchanged).

    		 None
    public_secure bool | None

    HTTPS for public_endpoint. None falls back to secure (unless a https:// scheme on public_endpoint forces it).

    		 None
    accel_redirect bool

    Delivery mode of :meth:serve_object. True answers with an X-Accel-Redirect for nginx to fetch the object (:meth:accel_redirect_response); False (default) streams the bytes through the app (:meth:download_response).

    		 False
    accel_prefix str

    Internal nginx location the X-Accel-Redirect points into, and the default internal_prefix of :meth:accel_redirect_response. Must start with /. Default "/_bucket/".

    		 '/_bucket/'
    enabled bool

    False builds a client for an integration switched off by STORAGE_ENABLED=false: no minio client is created (nor imported), and every operation — anything that reaches :attr:client — raises :class:~tempest_fastapi_sdk.exceptions.IntegrationDisabledException (503, details={"integration": "storage"}). StorageSettings.storage_kwargs passes it. Default True.

    		 True

    Raises:

    Type Description
    ValueError

    When accel_prefix does not start with /.
    ImportError

    When the minio package is not installed and enabled is True. Install the [minio] extra: pip install tempest-fastapi-sdk[minio].
    Notes

    In split-endpoint mode a second client is built with the same credentials, whose only job is signing presigned URLs against the public host. SigV4 signs the Host header, so the URL has to be signed with the public endpoint — rewriting the host afterwards would invalidate the signature.

    stream_object async ¶

    stream_object(
    key: str,
    *,
    bucket: str | None = None,
    chunk_size: int = 64 * 1024,
    offset: int = 0,
    length: int | None = None,
) -> AsyncIterator[bytes]

    Stream an object (or one byte range of it) in fixed-size chunks.

    The whole network read still runs in a worker thread — each chunk_size read is one asyncio.to_thread round-trip — but the event loop yields between chunks so other requests progress.

    offset and length are forwarded to Minio.get_object, which turns them into a Range header on the request to the store, so only that slice crosses the network — what a 206 response needs. A whole-object read (the defaults) still calls get_object(bucket, key) without them, so a test double written against the older two-argument call keeps working.

    Parameters:

    Name Type Description Default
    key str

    Object key.

    		 required
    bucket str | None

    Override source bucket.

    		 None
    chunk_size int

    Bytes per chunk. Default 64 KiB.

    		 64 * 1024
    offset int

    First byte to read. Default 0.

    		 0
    length int | None

    How many bytes to read from offset. None (default) reads to the end of the object.

    		 None

    Stream an object straight to the client as a download response.

    Reads the object's metadata (for the content type, length and validators) and streams its bytes through the app — the file never lands on the app's disk nor loads fully into memory. Reach for this when the download must be auth-gated or the MinIO endpoint is not publicly reachable; prefer :meth:presigned_get_url to offload the transfer to MinIO directly when the client can hit it.

    Every response carries Accept-Ranges: bytes plus the object's ETag (quoted) and Last-Modified, and the download security headers of :data:~tempest_fastapi_sdk.api.static.DEFAULT_STATIC_SECURITY_HEADERS, since the bytes reach the client on the API's origin with the type stored at upload. Pass request to let the client use the validators:

    • If-None-Match matching the ETag — or, when no If-None-Match is sent, If-Modified-Since not older than the object — answers 304 with no body, without reading the object.
    • Range: bytes=a-b, bytes=a- or bytes=-n answers 206 with Content-Range, reading only that slice from the store (offset/length on get_object). This is what lets a <video> seek and a download manager resume.
    • A range starting at or past the end answers 416 with Content-Range: bytes */<size>.
    • Several ranges (bytes=0-1,5-6), an unparseable Range, or an If-Range that no longer matches the object serve the whole object with 200 — RFC 9110 allows ignoring Range, and it avoids a multipart/byteranges body.

    Without request no request header is read and the response is always 200 with the whole object.

    Hand the transfer to nginx with an X-Accel-Redirect header.

    The route keeps the authorisation decision and nginx moves the bytes: the response is empty and carries X-Accel-Redirect: <internal_prefix><bucket>/<key>?X-Amz-..., a URL presigned against the internal endpoint — never public_endpoint — so the bucket stays private and the client only ever sees the backend's domain. nginx follows the header into an internal location that proxies to the bucket; the client's Range and If-None-Match travel with that request, so 206 and 304 come from the store itself.

    SigV4 signs the Host header and the path, so the internal location must strip the prefix (proxy_pass with a trailing /) and send Host equal to endpoint; otherwise the store answers 403 SignatureDoesNotMatch. The storage recipe carries the full nginx block.

    Content-Disposition, Content-Type and Cache-Control are not set on this response but signed into the URL as the S3 response-* overrides, so the store returns them with the bytes. Measured on nginx 1.27.5: the upstream's Content-Type wins over the one the app sets, and a Content-Disposition set on both reaches the client twice.

    The download security headers (:data:~tempest_fastapi_sdk.api.static.DEFAULT_STATIC_SECURITY_HEADERS) are not set here: S3 has no response-* override for them, and nginx answers with the store's response — measured on nginx 1.22.1, 1.27.5 and 1.29.8, a Content-Security-Policy the app sets on the empty response does not reach the client. They belong in the internal location, as add_header ... always; the storage recipe's nginx block carries them.

    No stat is made: a missing object surfaces as the store's 404 through nginx instead of an S3Error here.

    An :class:AsyncMinIOClient that signs each bucket with its own key.

    Built like :class:AsyncMinIOClient, plus bucket_credentials. The constructor arguments describe the primary credential, which answers every bucket missing from bucket_credentials; each listed bucket gets a client of its own with the same endpoint, region, TLS and public endpoint, and only its keys swapped.

    make_local_storage_router ¶

    make_local_storage_router(
    client: LocalObjectStorageClient,
    *,
    as_attachment: bool = False,
    cache_control: str | None = "private, no-store",
) -> APIRouter

    Build the GET/PUT/POST routes for a local store's signed links.

    • GET {route_prefix}/{bucket}/{key} verifies a download signature and streams the object with its stored content type, honouring Range and the validators (206/304/416) the same way :meth:AsyncMinIOClient.download_response <tempest_fastapi_sdk.storage.AsyncMinIOClient.download_response> does. A missing object answers 404 NOT_FOUND. A link signed with filename/media_type/as_attachment answers with those, the way S3 answers a link with signed response-* overrides.
    • PUT {route_prefix}/{bucket}/{key} verifies an upload signature and stores the raw body with the request's Content-Type. A Content-Length over :attr:LocalObjectStorageClient.max_upload_bytes is refused before reading; without it the body is counted while it streams and cut at the cap — 413 FILE_TOO_LARGE either way, and nothing is stored. Success answers 200 with the ETag, as S3 does.
    • POST {route_prefix}/{bucket}/{key} answers a :meth:LocalObjectStorageClient.presigned_post_policy form. The file must fit the signed [min_bytes, max_bytes] — 413 FILE_TOO_LARGE / 400 FILE_TOO_SMALL otherwise — and the key and Content-Type fields must match the signed ones (403 SIGNED_URL_INVALID). Success answers 204 with the ETag, as S3 does. Reading the form needs python-multipart ([upload]).

    A tampered, unsigned or wrong-purpose link answers 403 SIGNED_URL_INVALID, an expired one 403 SIGNED_URL_EXPIRED. Both routes stay out of the OpenAPI schema.

    With encryption_keys on the client the routes do not change shape: PUT and POST store the body encrypted, the caps count the plaintext, and GET (Range included) answers the plaintext. A stored file whose first served block fails its check answers 500 STORAGE_INTEGRITY_ERROR with no byte of it; a later block that fails cuts the connection after the blocks that verified.

    Build the tus routes createResumableUpload talks to.

    Every response of these routes carries Tus-Resumable: 1.0.0, and so does every refusal raised while handling them (the router's errors and a 401/403 from current_user_id); an unhandled 500 is answered by the app without it. Errors use the SDK envelope (detail/code/details) through :class:~tempest_fastapi_sdk.AppException, so mount the app with :func:~tempest_fastapi_sdk.register_exception_handlers as usual.

    TusCompleteCallback ¶

    Bases: Protocol

    Called exactly once per upload, after its last byte is stored and finalized.

    Receives the upload and the store, so it can read the file with :meth:TusStore.stream <tempest_fastapi_sdk.storage.tus.TusStore.stream> (or :meth:LocalTusStore.data_path <tempest_fastapi_sdk.storage.tus.LocalTusStore.data_path> / :meth:S3TusStore.object_key <tempest_fastapi_sdk.storage.tus.S3TusStore.object_key>) and register, move or delete it.     TusUpload dataclass ¶

    TusUpload(
    id: str,
    length: int,
    offset: int = 0,
    metadata: dict[str, str] = dict(),
    owner: str | None = None,
    created_at: datetime = (lambda: now(UTC))(),
    expires_at: datetime | None = None,
    idempotency_digest: str | None = None,
    notified: bool = False,
)

    One resumable upload, as a tus store keeps it.

    The record is the authority on how many bytes are stored: a chunk is written first and the record saved after, so a crash between the two leaves offset at the last confirmed byte and the next PATCH overwrites whatever was half-written past it.

    Attributes:

    Name Type Description
    id str

    Unguessable id, the last segment of the upload URL.
    length int

    Total size the client declared in Upload-Length.
    offset int

    Bytes stored so far.
    metadata dict[str, str]

    Decoded Upload-Metadata pairs, as the client sent them. Read the name through :attr:filename, never from here, before using it in a path.
    owner str | None

    str() of what current_user_id resolved when the upload was created; None for an anonymous upload.
    created_at datetime

    Creation time, UTC.
    expires_at datetime | None

    When an incomplete upload stops being resumable. Renewed by every accepted PATCH; None when the router has no expiration.
    idempotency_digest str | None

    SHA-256 of owner and Idempotency-Key, when the creation carried one.
    notified bool

    Whether on_complete returned without raising. A complete upload with notified false is one the service still has to handle.
