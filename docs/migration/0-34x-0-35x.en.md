# Migration 0.34x–0.35x

Use when upgrading from a version older than these releases: 0.353.0, 0.349.0, 0.344.0, 0.343.0, 0.342.0, 0.341.0 and 0.340.0.

Part of the [Migration guide](../migration.md).

## 0.353.0 — Gemini's `google_kwargs()` becomes `gemini_kwargs()`

`HostedGenAISettings.google_kwargs()` (Gemini) and `OAuthSettings.google_kwargs(prefix=...)` (Google login) shared a name. A `Settings` composing both kept the first one in the MRO, and Google login broke with `TypeError` on `prefix`. The Gemini one was renamed, with no alias (an alias would keep the clash).

| Where | What changes | What to do |
| --- | --- | --- |
| `HostedGenAISettings` | `google_kwargs()` is now `gemini_kwargs()`; same return value, same `ValueError` when `GOOGLE_MODEL` is empty | `OpenAICompatGenerator(**settings.google_kwargs())` becomes `OpenAICompatGenerator(**settings.gemini_kwargs())`. With the old name, a `Settings` with only `HostedGenAISettings` raises `AttributeError` |
| `OAuthSettings` | **Nothing**: `google_kwargs(prefix=...)` is still the Google login one | Nothing; services composing both mixins now get the right method |
| `WebPushSettings` / `FirebaseSettings` | `enabled` becomes `webpush_enabled` and `firebase_enabled`, with no alias. Both had the same name and different meanings, and a `Settings` composing both without `PushSettings` read the answer of the first one in the MRO (#742) | `settings.enabled` on a service with `WebPushSettings` becomes `settings.webpush_enabled`; with `FirebaseSettings`, `settings.firebase_enabled`. The old name raises `AttributeError`. `PushSettings.enabled`, `web_enabled` and `mobile_enabled` **do not change** |

## 0.349.0 — Coqui in its own extra, oversized upload as 413 and a stricter `tempest check`

| Where | What changes | What to do |
| --- | --- | --- |
| `[genai-audio]` | No longer brings `coqui-tts`, `torchaudio`, `torchcodec` or `six`: `TextToSpeech` (XTTS) moves to the new `[genai-tts-coqui]` extra. `SpeechToText` is unchanged | If you use `TextToSpeech`, install `[genai-audio,genai-tts-coqui]` (or just `[genai-tts-coqui]`, without STT). Otherwise the first synthesis raises `ImportError` naming `[genai-tts-coqui]` |
| `read_upload_capped` and the routes that use it (`make_genai_router`'s `/transcribe`, `make_voice_router`, `make_vision_router`) | An upload over the ceiling raises `UploadTooLargeException` (`413`, `code` `UPLOAD_TOO_LARGE`) instead of `ValidationException` (`422`, `VALIDATION_ERROR`). `detail` and `details.max_bytes` are unchanged | A client that handled the size `422` handles `413` instead. A service that caught `ValidationException` to re-raise as `413` can drop the wrapper; `except FileTooLargeException` also catches the new exception |
| `tempest check` | Runs two new steps between `mypy` and `pytest`: `openapi-errors` (the same `--check`, which also fails on a declared but unreachable exception) and `lint-schemas`. And `openapi-errors` now follows FastAPI dependencies, so a route whose router requires `require_token` or whose provider answers 404 reports what it did not declare | Run `tempest openapi-errors --check` and `tempest lint-schemas` and fix; `tempest openapi-errors --fix` writes the missing declarations. To migrate gradually, `check_openapi_errors = false` / `check_lint_schemas = false` under `[tool.tempest]` |

## 0.344.0 — token of a deleted account

| Where | What changes | What to do |
| --- | --- | --- |
| `UserAuthService.current_user_dependency` | A valid token of a deleted account (or a `sub` that is not a UUID) answers `401 UNAUTHORIZED` instead of `404 NOT_FOUND`; with `soft=True`, the dependency yields `None` | Nothing, if the client already treats `401` as session over. Whoever handled the `404` of those routes switches to `401`; whoever reimplemented the loader just to translate the `404` can go back to `current_user_dependency()` |

## 0.343.0 — every SDK enum ends in `Enum`

Eighty hand-written public enums gained the suffix the others already had
(`PdfExtractor` → `PdfExtractorEnum`, `JobStatus` → `JobStatusEnum`,
`UF` → `UFEnum`). There is no alias: the old name is gone, and the import
fails immediately.

```text
ImportError: cannot import name 'JobStatus' from 'tempest_fastapi_sdk.tasks'
```

| Where | What changes | What to do |
| --- | --- | --- |
| `import` and type annotations | The old name no longer exists | Use the new name from the table below; your editor's symbol rename (not a text replace) keeps "UF" or "Locale" in prose intact |
| Your service's OpenAPI | The component carries the class name: `JobStatus` becomes `JobStatusEnum` | Regenerate the frontend client; anything referencing `#/components/schemas/JobStatus` by hand updates the reference |
| Serialized value (JSON, database) | **Nothing**: `JobStatusEnum.QUEUED` is still `"queued"` | Nothing |
| Native Postgres type | **Nothing**: `TempestEnum` and `enum_column` drop one trailing `Enum` before naming the type, so `JobStatus` and `JobStatusEnum` both yield `job_status_enum` (measured on all 80) | Nothing; no migration is generated |

Enums generated from a provider's specification (OpenPix, Mercado Pago,
zap-api, `StripeEvent`) keep the specification's name.

## 0.342.0 — required `ENV` and empty `X-Token` secret

| Where | What changes | What to do |
| --- | --- | --- |
| `EnvironmentSettings.ENV` | **No default** (was `development`): settings composing the mixin with no `ENV` in the environment or the `.env` raise `ValidationError` (`ENV Field required`) at boot | Set `ENV` in every environment — dev `.env`, container, CI, worker, migration job. In `conftest.py`, `os.environ["ENV"] = "test"` before importing the app |
| `UserAuthService` with `AuthSettings` but no `EnvironmentSettings` | Reads `ENV` from the environment; **an unset `ENV` counts as production**: without a mailer (or with `AUTH_RETURN_TOKEN_IN_RESPONSE`), link-carrying flows answer `503 INTEGRATION_DISABLED` instead of returning the link | In dev, `ENV=development`; in production, wire the mailer. A panel that created accounts or replaced passwords by composing `signup` + `activate` or the reset: use `admin_create_user` / `admin_set_password` (0.364.0+), which skip the mailer |
| `make_token_dependency`, `require_x_token` | An empty (or whitespace-only) secret raises `ValueError` instead of disabling the check | Configure the secret (`tempest secrets init`); for a local run without the gate, pass `allow_unauthenticated=True`. A project generated by `tempest new`: replace the line in `src/api/dependencies/auth.py` with `make_token_dependency(settings.TOKEN_SECRET, allow_unauthenticated=settings.ENV != "production")` |

## 0.341.0 — Mercado Pago webhook and `.xlsx` formulas

| Where | What changes | What to do |
| --- | --- | --- |
| `verify_signature`, `make_mercado_pago_webhook_dependency` and `make_mercado_pago_webhook_delivery_dependency` | `tolerance_seconds` goes from `None` to `DEFAULT_TOLERANCE_SECONDS` (`300.0`): a delivery whose `ts` is more than five minutes off the clock becomes `False` / 401 | Nothing, with a synchronized clock. A test signing a fixed `ts` passes `now=` or `tolerance_seconds=None`; whoever wants the upstream behaviour passes `tolerance_seconds=None` |
| `SheetWriter` (`write_row`, `header_row`, `title_block`) | A `str` starting with `=` is written as text, not as a formula | Wrap the legitimate formula in `Formula("=SUM(B5:B24)")` |

## 0.340.0 — sign-up, Web Push and SSE

| Where | What changes | What to do |
| --- | --- | --- |
| `UserAuthService.signup(fields=...)` | Also refuses `last_login_at`, `created_at`, `updated_at`, `deleted_at`, `created_by` and `updated_by` with `ValueError` (`make_auth_router` already drops those names from a `signup_schema`) | Remove those keys from `fields=`; whoever needs to fill authorship or a timestamp does it after the sign-up, in their own service |
| `WebPushDispatcher.send_many` | An endpoint refused by a DNS answer is returned for pruning after 3 consecutive refusals spread over at least 1 hour (`prune_after_dns_refusals`, `dns_refusal_window_seconds`); a browser push service host is never pruned this way | Nothing, with a public push service. A self-hosted push service on the internal network without `allow_private_networks=True`: pass `prune_after_dns_refusals=None` to keep the old behaviour |
| `SSEBroker` with Redis | The published envelope gains a `prefix` field, and the receiver drops another prefix's; an envelope without the field is still delivered | Nothing. During a rolling deploy, old and new workers coexist |
