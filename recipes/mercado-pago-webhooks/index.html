    Mercado Pago: testando webhooks¶

    Webhook é a parte mais difícil de testar de uma integração de pagamento: quem chama é o Mercado Pago, não você, e ele precisa de uma URL pública para chamar. Esta página mostra quatro níveis de teste, do que roda sem rede nenhuma até a entrega real:

    1. Simulado pelo SDK, sem rede — a API de Orders e a notificação são simuladas; o adapter de verdade cria, relê e estorna sobre elas. Nem credencial, nem sandbox. Comece por aqui — na suíte e no teste manual.
    2. Simulação assinada sobre o sandbox — você assina uma notificação com o seu segredo e entrega na sua rota. A rota relê uma order real do sandbox. Não precisa de URL pública.
    3. "Simular notificação" do painel — o Mercado Pago manda uma notificação de teste para a sua URL.
    4. Entrega real — você cria uma order e o Mercado Pago avisa sozinho.

    Antes, tenha em mãos as credenciais da receita contas e credenciais de teste e entenda o que a rota faz em Mercado Pago »: ela verifica a assinatura e relê a order, porque a notificação não traz o estado do pagamento.

    Nível 1 — simulado pelo SDK, sem rede¶

    O SDK traz o Mercado Pago simulado em tempest_fastapi_sdk.testing.fakes:

    • FakeMercadoPagoOrdersAPI responde /v1/orders com estado — cria (idempotente pela X-Idempotency-Key), relê, cancela, captura e estorna. É um handler do httpx, então o MercadoPagoPixProvider de verdade roda sobre ele sem mudança nenhuma: MercadoPagoPixProvider(api.http_client()).
    • Os movimentos que só o provedor faz são métodos — pay, expire, fail, cancel, capture, refund — e cada um devolve a notificação assinada que anuncia o novo estado, pronta para delivery.send(client, rota).
    • build_mercado_pago_delivery(order, secret=...) monta a notificação sozinha, no formato da entrega real observada em produção, assinada pelo mesmo sign_manifest que o verificador do SDK usa.

    O script cria cobranças pelo adapter, move cada uma e entrega a notificação na rota montada como o seu serviço monta:

    import asyncio
from typing import Any

import httpx
from fastapi import Depends, FastAPI

from tempest_fastapi_sdk.integrations.payment import PixChargeRequest, PixPayer
from tempest_fastapi_sdk.integrations.payment.adapters import (
    MercadoPagoOrderDelivery,
    MercadoPagoPixProvider,
    make_mercado_pago_webhook_delivery_dependency,
)
from tempest_fastapi_sdk.testing.fakes import (
    FakeMercadoPagoOrdersAPI,
    MercadoPagoDelivery,
)

SECRET: str = "segredo-local-de-teste"


def build_app(provider: MercadoPagoPixProvider) -> FastAPI:
    """Mount the webhook route exactly as the service would."""
    app = FastAPI()
    dependency = make_mercado_pago_webhook_delivery_dependency(SECRET, provider)

    @app.post("/webhooks/mercado-pago")
    async def webhook(
        delivery: MercadoPagoOrderDelivery = Depends(dependency),
    ) -> dict[str, Any]:
        """Report what the re-read decided."""
        event = provider.parse_webhook(delivery)
        return {
            "type": event.type.value,
            "status": event.charge.status.value if event.charge else None,
        }

    return app


async def deliver(app: FastAPI, delivery: MercadoPagoDelivery) -> tuple[int, Any]:
    """Send one signed delivery to the route, in-process."""
    async with httpx.AsyncClient(
        transport=httpx.ASGITransport(app=app), base_url="http://local"
    ) as client:
        answer = await delivery.send(client, "/webhooks/mercado-pago")
    return answer.status_code, answer.json()


async def main() -> None:
    """Run payment, refund, cancellation and expiry with no network."""
    api = FakeMercadoPagoOrdersAPI(webhook_secret=SECRET)
    provider = MercadoPagoPixProvider(api.http_client(), action_retry_delays=())
    app = build_app(provider)
    payer = PixPayer(email="comprador@example.com")

    async def new_charge(reference: str) -> str:
        """Create a R$ 19,90 Pix charge through the real adapter."""
        charge = await provider.create_pix_charge(
            PixChargeRequest(amount_cents=1990, reference=reference, payer=payer)
        )
        return charge.provider_charge_id

    paid = await new_charge("pedido-1")
    print("criada    ", await deliver(app, api.delivery(paid)))
    print("paga      ", await deliver(app, api.pay(paid)))
    await provider.refund_pix_charge(paid, 500, refund_reference="estorno-1")
    print("parcial   ", await deliver(app, api.delivery(paid)))
    await provider.refund_pix_charge(paid, refund_reference="estorno-2")
    print("estornada ", await deliver(app, api.delivery(paid)))

    cancelled = await new_charge("pedido-2")
    await provider.cancel_pix_charge(cancelled)
    print("cancelada ", await deliver(app, api.delivery(cancelled)))
    print("vencida   ", await deliver(app, api.expire(await new_charge("pedido-3"))))

    stranger = FakeMercadoPagoOrdersAPI(webhook_secret="outro-segredo")
    await MercadoPagoPixProvider(stranger.http_client()).create_pix_charge(
        PixChargeRequest(amount_cents=1990, reference="x", payer=payer)
    )
    print("forjada   ", await deliver(app, stranger.delivery(stranger.order_ids[0])))
    other = FakeMercadoPagoOrdersAPI(webhook_secret=SECRET)
    await MercadoPagoPixProvider(other.http_client()).create_pix_charge(
        PixChargeRequest(amount_cents=1990, reference="y", payer=payer)
    )
    print("simulada  ", await deliver(app, other.delivery(other.order_ids[0])))


asyncio.run(main())

    Linha O que aconteceu Por que importa
    criada order recém-criada, relida action_required → charge_created o tipo do evento sai da releitura, não do corpo
    paga api.pay → relida processed → charge_paid é o caminho que libera o pedido; agora roda na suíte
    parcial estorno de R$ 5,00 → continua processed → charge_paid estorno parcial não é estorno total
    estornada o resto estornado → refunded → charge_refunded o adapter soma os estornos pela releitura

    vencida api.expire → canceled / expired → charge_expired vencer não é cancelar: são eventos distintos no contrato
    forjada outro segredo → 401, sem chamada à API quem não tem o segredo não chega na releitura
    simulada id que a API não conhece → 404 na releitura → 200 sem cobrança é provavelmente o que o painel manda no nível 3 (ainda não observado)

    Na sua suíte

    O mesmo código vira teste: troque os print por assert. A suíte do SDK faz exatamente isso em tests/integrations/payment/adapters/test_mercado_pago_simulated_flow.py — Pix pago, estornado em duas vezes, cancelado, vencido, e cartão aprovado, autorizado e capturado, e recusado (api.decline_next_card()).

    O que a simulação copia, e o que ela supõe

    Os estados de cada transição, os códigos de resposta (201, 200, 402, 404), a regra de idempotência e o 409 cannot_refund_order foram copiados do sandbox. O formato da notificação foi copiado de uma entrega real, order.canceled. As outras ações (order.processed, order.refunded, order.failed, order.action_required) não foram observadas e também não estão no documento que o SDK vendoriza, que só lista order.created / order.updated: o simulador as nomeia pelo status da order. A rota do SDK não decide pela ação — relê a order —, então isso não muda o resultado; muda só se o seu código ler action.

    Supostos, não copiados: o 409 cannot_cancel_order (e a mensagem "The order cannot be canceled in status …"), o código e a mensagem do 404 de order inexistente (order_not_found, "Order … not found" — só o status 404 foi medido) e o 400 invalid_refund_amount do estorno acima do saldo, com a mensagem dele. Se o seu código lê code ou message dessas respostas, confira no sandbox.

    Teste manual: o serviço rodando, o Mercado Pago simulado¶

    O mesmo simulador sobe como servidor, e o serviço aponta para ele por MERCADOPAGO_BASE_URL (campo do MercadoPagoSettings, default https://api.mercadopago.com). Um serviço mínimo, com a rota de criar cobrança e a de webhook:

    from typing import Any

import uvicorn
from fastapi import Depends, FastAPI

from tempest_fastapi_sdk import HTTPClient
from tempest_fastapi_sdk.integrations.payment import PixChargeRequest, PixPayer
from tempest_fastapi_sdk.integrations.payment.adapters import (
    MercadoPagoOrderDelivery,
    MercadoPagoPixProvider,
    make_mercado_pago_webhook_delivery_dependency,
)
from tempest_fastapi_sdk.settings import MercadoPagoSettings

settings = MercadoPagoSettings()
provider = MercadoPagoPixProvider(HTTPClient(**settings.mercado_pago_kwargs()))
app = FastAPI()
webhook_dependency = make_mercado_pago_webhook_delivery_dependency(
    settings.MERCADOPAGO_WEBHOOK_SECRET, provider
)


@app.post("/charges")
async def create_charge(reference: str) -> dict[str, Any]:

    charge = await provider.create_pix_charge(
        PixChargeRequest(
            amount_cents=1990,
            reference=reference,
            payer=PixPayer(email="comprador@example.com"),

    return {"order_id": charge.provider_charge_id, "status": charge.status.value}


@app.post("/webhooks/mercado-pago")

    A rota pronta: make_mercado_pago_router¶

    A rota de webhook acima é a mesma em todo serviço: verificar, reler, entregar ao seu código, responder 200. make_mercado_pago_router monta essa rota a partir da dependência make_mercado_pago_webhook_delivery_dependency — a verificação e a releitura são as mesmas — e você escreve só o handler:

    app.include_router(make_mercado_pago_router(provider, on_delivery=handle, settings=settings, simulate=settings.ENV == "development")) — o serviço completo está no exemplo de Front em desenvolvimento, logo abaixo.

    • on_delivery(delivery: MercadoPagoOrderDelivery) -> Awaitable[None] recebe a entrega já verificada, com a order relida. Retornou: a rota responde 200 com {"ok": true, "data_id": ..., "order_status": ...}. Levantou: a resposta é 500 — e, pela documentação do provedor, o Mercado Pago entrega de novo (reenvio esperado, não observado aqui).
    • O segredo vem de secret=; sem ele, de settings.MERCADOPAGO_WEBHOOK_SECRET (ou do ambiente e do .env, quando settings também falta). Segredo vazio é recusado na construção (ValueError): ele recusaria toda entrega.
    • webhook_path tem default /webhooks/mercado-pago — é a URL que você cadastra no painel.
    • Quem já escreve a rota à mão com a dependência continua igual: nada mudou nela.

    Front em desenvolvimento: simulate=True¶

    Com simulate=True, o router monta também as rotas que o front usa para fazer o que só o Mercado Pago faz — pagar, vencer, recusar, cancelar, capturar, estornar:

    Rota O que faz
    GET /dev/mercado-pago/orders todas as orders do simulador
    GET /dev/mercado-pago/orders/{order_id} uma order; 404 se não existe
    POST /dev/mercado-pago/orders/{order_id}/{transition} pay, expire, fail, cancel, capture, refund (?amount_cents= para estorno parcial)

    Cada transição muda a order na FakeMercadoPagoOrdersAPI em memória sobre a qual o seu provider roda, assina a notificação com o segredo da rota e a entrega à rota de webhook do próprio serviço, pelo app inteiro (httpx.ASGITransport(request.app)): middleware, verificação da assinatura, releitura e on_delivery rodam de verdade. A resposta traz a order depois da transição e o que a rota de webhook respondeu. Transição que o estado não permite (estornar antes de pagar) é 409; order desconhecida, 404; transição desconhecida, 422. No Swagger, essas rotas aparecem sob a tag mercado-pago (dev).

    {order_id} aceita também o external_reference que você mandou na criação — o reference do PixChargeRequest, em geral o seu correlation_id, que é o que a sua tela e o seu log mostram. Quando várias orders compartilham o mesmo, a mais recente é a movida: cobrar de novo a mesma referência depois de um vencimento quer dizer a order nova.

    O provider se liga ao simulador por mercado_pago_provider_for: com simulate=False ele devolve o MercadoPagoPixProvider sobre settings.mercado_pago_kwargs(); com simulate=True, o mesmo adapter sobre uma FakeMercadoPagoOrdersAPI em memória, e o router acha o simulador sozinho (simulation_api_for(provider)).     Saque manual¶

    O payout do Mercado Pago não está liberado para a conta (#499). Enquanto isso, o router faz o saque por um administrador: com withdraw=, ele monta POST /api/mercado-pago/withdraw, que:

    1. debita todo o saldo disponível do usuário pelo WalletService.withdraw — a rota não aceita valor, a carteira fica zerada;
    2. grava a linha PENDING da tabela de saques manuais (make_manual_payout_model), com a chave mascarada;
    3. manda ao administrador o e-mail com valor, chave Pix e tipo, user_id, correlation_id e o link da linha no painel.

    O usuário e a chave vêm das mesmas dependências do make_wallet_router (current_user_id, pix_destination — a chave vem do perfil, nunca do corpo). O e-mail sai pelo ManualPayoutProvider, que aceita qualquer objeto com o send(to, subject, body) do EmailUtils: em produção, EmailUtils(**settings.email_kwargs()); em desenvolvimento, o FakeEmailUtils guarda a mensagem em outbox.

    O histórico que o usuário vê no app ("SAQUE SOLICITADO") é do serviço. Para ele entrar no mesmo commit da linha, passe hooks=ManualPayoutHooks(...) ao MercadoPagoWithdrawConfig: o on_requested recebe a sessão e a linha PENDING dentro da transação que a grava. Se ele levantar, nada é gravado — nem a linha, nem o histórico —, nenhum e-mail sai e a rota responde 502 WALLET_PAYOUT_REJECTED com o débito devolvido. hooks exige record_model: sem linha, não há transação para o callback entrar, e o config recusa com ValueError. A mesma instância vai ao ManualPayoutService para on_paid e on_rejected — veja Carteira » Concluir ou recusar o saque à mão.

    No painel: anexar o comprovante e marcar como pago¶

    manual_payout_admin(ManualPayoutModel, upload_storage=...) registra a tabela no painel do jeito que o trabalho pede:

    • lista filtrável por status e buscável por correlation_id;
    • valor, usuário, chave, tipo, correlation_id, status e quem concluiu são só leitura; não há criar, apagar nem importar;
    • receipt_key é um upload que aceita só PDF: o tipo declarado tem de ser application/pdf e os bytes têm de começar com %PDF- — um PNG renomeado para .pdf é recusado com erro no campo, e nada é gravado;
    • a página da linha tem o link Download do comprovante;
    • a ação Marcar como pago conclui só linhas PENDING com comprovante, gravando completed_at e completed_by (o administrador logado); linha sem comprovante fica PENDING e a mensagem lista os correlation_id dela;

def build_app(provider: MercadoPagoPixProvider) -> FastAPI:
    """Mount the webhook route exactly as the service would."""
    app = FastAPI()
    dependency = make_mercado_pago_webhook_delivery_dependency(SECRET, provider)

    @app.post("/webhooks/mercado-pago")
    async def webhook(
        delivery: MercadoPagoOrderDelivery = Depends(dependency),
    ) -> dict[str, Any]:
        """Report what the re-read decided."""
        event = provider.parse_webhook(delivery)
        return {
            "type": event.type.value,
            "status": event.charge.status.value if event.charge else None,
        }

    return app


def signed_headers(order_id: str) -> dict[str, str]:
    """Sign a notification for this order the way Mercado Pago does."""
    request_id = str(uuid.uuid4())
    ts = str(int(time.time()))
    digest = sign_manifest(
        secret=SECRET, data_id=order_id, request_id=request_id, timestamp=ts
    )
    return {"x-signature": f"ts={ts},v1={digest}", "x-request-id": request_id}


async def notify(app: FastAPI, order_id: str, headers: dict[str, str]) -> tuple[int, Any]:
    """Deliver one notification to the local route, in-process."""
    async with httpx.AsyncClient(
        transport=httpx.ASGITransport(app=app), base_url="http://local"
    ) as client:
        answer = await client.post(
            f"/webhooks/mercado-pago?data.id={order_id}&type=order",
            headers=headers,
            json={"action": "order.updated", "type": "order", "data": {"id": order_id}},
        )
    return answer.status_code, answer.json()

    3. Copie a assinatura secreta que o painel gera e use como MERCADO_PAGO_WEBHOOK_SECRET no seu serviço.
    4. Use Simular notificação.

    Recapitulando¶

    • A notificação só diz qual order mudou; a rota relê para saber o quê.
    • FakeMercadoPagoOrdersAPI + o adapter de verdade testam pagamento, estorno, cancelamento e vencimento sem rede; tempest mercado-pago fake-api e simulate-webhook fazem o mesmo com o serviço rodando.
    • make_mercado_pago_router monta a rota de webhook; com simulate=True (só em development/test), o front paga e estorna pelas rotas /dev/mercado-pago/..., que entregam o webhook à rota de verdade; com withdraw=, o saque zera a carteira e vira um Pix manual que o administrador conclui no painel, com o comprovante em PDF.
